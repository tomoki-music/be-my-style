# Business「Social Atelier」デザイン方針と実装記録

Business（NAKAMA）のログイン後画面を「Social Atelier」という方針で統一したときの設計資料です。
見た目だけでなく、情報の配置・ナビゲーション・操作の分かりやすさを揃えました。
権限・料金プラン・参加承認・データ・業務ロジックは変えていません。

- ブランチ: `feature/business-social-atelier-redesign`（2026-10-29 作業）
- 対象: Business のログイン後画面
- 対象外: ログイン前の紹介ページ（`/business` 未ログイン）、Business 認証画面（`shared/domain_auth`）、音楽側、システム管理画面、Stripe 側の画面
- 追加改修: `feature/business-login-join-flow`（2026-10-30）で、ログインの案内・音楽コミュニティ導線の除去・参加導線を整理した（[9 章](#9-実機確認を受けた追加改修2026-10-30)）
- 追加改修: `feature/business-landing-atelier`（2026-10-30）で、ログイン前の紹介ページ（`/business` 未ログイン）も Social Atelier に揃えた（[10 章](#10-ログイン前の紹介ページ2026-10-30)）
- 追加改修: `feature/business-blue-brand`（2026-10-30）で、ロゴを NAKAMA の青いロゴに差し替え、配色を紫から青に統一した（[11 章](#11-nakama-の青いロゴと配色2026-10-30)）。1・2 章の色は改修後の値
- 追加改修: `feature/business-help-and-timeline`（2026-10-30）で、利用イメージのイラスト・使い方ページ（`/business/help`）を追加し、ビジネス投稿の一覧をタイムラインに統一した（[12 章](#12-利用イメージのイラスト使い方ページタイムラインの整理2026-10-30)）
- 追加改修: `feature/business-join-theme-share-help`（2026-10-30）で、プロジェクトの参加表現の統一・「目標」「締切」の取りやめと「テーマ」の追加・招待用URLのコピー・使い方の「一般ユーザー向け／管理者向け」の切り替えを行った（[13 章](#13-参加表現テーマ招待用url使い方の切り替え2026-10-30)）

## 1. デザイン方針

| 観点 | 方針 |
|------|------|
| 雰囲気 | 写真・アイコンで「誰が・何をしているか」が伝わる、親しみやすい SNS 的な構成。特定サービスの画面・ロゴは複製しない |
| 色 | 白を基調に、ページ背景（`#F7F9FC`）とカード（白）を薄く区別する。アクセントは NAKAMA ロゴのブランドブルー（`#2864D9`）、補助にロゴのスカイブルー（`#55BCEB`）を淡くした面と、種別ラベルのピーチ（2026-10-30 にバイオレットから変更） |
| グラデーション | 画像がないときの頭文字の背景と、カバー画像がないときの細い帯だけに使う |
| 文字 | 本文 16px・行間 1.6〜1.75。本文は濃いグレー（`#1F2633`）でコントラストを確保する |
| 形 | コミュニティは丸い画像、プロジェクトは画像付きカード。角丸・線・影はトークンの値に揃える |
| 画像なし | 名前の頭文字（`business_monogram`）で代替する。ダミー画像は追加しない |
| 装飾 | 意味のない英語コピー、大きなヒーロー、装飾目的のアニメーションは入れない |
| 状態表示 | 色だけで伝えない。「参加中」「承認待ち」「停止中」などの文字と記号を必ず付ける |
| 操作 | タップ領域は原則 44px 以上。hover だけに頼らず、フォーカスリングを表示する |
| 動き | 状態変化の短いトランジションのみ。`prefers-reduced-motion: reduce` では無効にする |

## 3. コンポーネント規約

| 部品 | クラス | 使い方 |
|------|--------|--------|
| カード | `.ba-card` | 画面内のまとまり。中の見出しは `.ba-section-title` |
| ページ見出し | `.ba-page-header` / `.ba-page-title` / `.ba-page-lead` / `.ba-page-actions` | 画面ごとに1つの h1。ページ固有の操作（作成など）は右側に置く |
| パンくず | `nav.ba-breadcrumb > ol > li` | 最後の項目は `aria-current="page"`。長い名前でも文章として折り返す |
| ボタン | `.ba-btn` + `--primary` / `--secondary` / `--soft` / `--success` / `--danger`、`--sm` | 主操作は1画面1つを目安に `--primary`。重大操作（停止・削除）は `--danger`（赤枠） |
| 状態 | `.ba-status` + `--member` / `--manager` / `--owner` / `--pending` / `--suspended` / `--kind` | 必ず文字と記号を一緒に出す |
| アバター | `.ba-avatar`、`business_community_avatar` | コミュニティは丸。画像がなければ `business_monogram` の頭文字 |
| 人 | `.ba-person`（`__avatar` / `__name` / `__meta`） | メンバー・申請者・オーナー・投稿者の表示 |
| 一覧の行 | `.ba-rows > .ba-row`（`__main` / `__actions`） | メンバー管理・プロジェクト管理。狭い幅では操作が下に回り込む |
| フォーム | `.ba-form` > `.ba-fieldset`（`legend.ba-fieldset__legend`）> `.ba-field`（`.ba-label` / `.ba-help`） | 入力項目を意味のあるまとまりに分ける。保存・キャンセルは `.ba-form-actions` に「主 → 副」の順 |
| エラー | `.ba-errors`（`role="alert"`） | フォームの先頭 |
| 空状態 | `.ba-empty`（`__title` / `__actions`） | 次に何をすればよいかの導線を置く |
| ページ内切替 | `nav.ba-sectnav` + `.ba-anchor-target` | `#about` などのアンカーで移動。URL・戻る操作と一致し、JS を使わない |
| 管理入口 | `shared/_manage_bar`（音楽側と共通の部品） | `.ba-body` 配下だけで見た目を変更。権限のある人だけに出す |
| 投稿 | `business/chat/_post`（`.ba-post`） | アバター → 名前・オーナー表示・時刻 → 本文 → 削除（本人のみ） |
| プロジェクトカード | `business/projects/_card`（`.ba-project-card`） | ホーム・プロジェクト一覧・コミュニティ通常画面で共通 |

### スコープの決まり

- Social Atelier のスタイルは、すべて `body.ba-body` 配下に書きます（`layouts/business` だけが `ba-body` を付けます）。
- 新しいマークアップは `ba-` 接頭辞のクラスだけを使います。既存の Business 用 SCSS には `.card` / `.btn-danger` などスコープのない定義があるため、新しい画面ではそれらのクラス名を使いません。
- 共有パーシャル（`feature_gate` / `subscription_manager` / Danger Zone / スタンプ選択 / 管理メニュー）は変更せず、`.ba-body` 配下で見た目だけを合わせています。
- リンクの色は `:where(a:not([class]))` で詳細度を上げずに付け、部品側の配色を上書きしないようにしています。

## 4. 画面レイアウトとナビゲーション

### 枠の構成（`layouts/business` → `layouts/_business_shell`）

| 幅 | 構成 |
|----|------|
| 〜991px（スマホ・タブレット縦） | 上部バー（ロゴ） + 本文 + 下部ナビ（5項目） + メニューシート |
| 992〜1199px | 左のアイコンナビ（96px、ラベルは小さく下に表示。プロフィール設定は「設定」と短く表示） |
| 1200px〜 | 左ナビ（240px、アイコン + ラベル） |

- 下部ナビ: **ホーム / コミュニティ / プロジェクト / 通知 / メニュー**
  - メニュー（シート）: プロフィール（名前つき）/ タイムライン / 投稿（プラン制限の表示つき）/ プロフィール設定 / ログアウト
- 左ナビ: ホーム / コミュニティ / プロジェクト / タイムライン / 投稿 / 通知、下部にプロフィール / プロフィール設定 / ログアウト
- 現在地は色に加えて、線（下部ナビは上端、左ナビは左端）と `aria-current="page"` で示します。
- 通知の未読件数はバッジと `aria-label`（例:「通知（未読4件）」）の両方で伝えます。件数は1回だけ数え、両方のナビで使います。
- iPhone のセーフエリア: `viewport-fit=cover`（Business のログイン後だけ）と `env(safe-area-inset-*)`。
- 画面キーボード: SP で文字入力欄（textarea・テキスト系 input）にフォーカスがある間だけ下部ナビを隠し（`body.ba-is-typing`）、入力欄・送信ボタンと重ねません。セレクト・日付・ファイル選択・スタンプ選択は OS の選択画面やパネルが出るだけなので、下部ナビは表示したままにします。
- メニューシート: `role="dialog"`。開くと「閉じる」にフォーカスし、Escape・閉じる・背景で閉じてメニューボタンへ戻します。開いている間は Tab がシート内で循環します（`business/atelier_nav.js`）。
- 本文へスキップするリンク（`.ba-skip-link`）を先頭に置いています。
- 旧ヘッダー（`layouts/_header_menu_nakama`）はログイン前の紹介ページだけで使い続けています。ログイン後の画面では、ヘッダーとナビの重複をなくしました。
- 新しい検索・DM・未読管理などの機能は追加していません。ナビの項目は既存のページだけです。

### 8.3 ナビゲーションと共用画面

実ブラウザの system spec（`spec/system/business/atelier_navigation_spec.rb` ほか）で確認しました。

- 下部ナビは文字入力中だけ隠れ、セレクト・日付・ファイル選択・スタンプ選択の操作では表示されたまま。入力欄から離れると戻る。
- メニューシートは、Enter で開き、Escape・閉じる・背景で閉じてフォーカスがメニューボタンへ戻る。開いている間は Tab がシート内で循環する。リンクで移動した後・ブラウザの「戻る」の後は閉じた状態で表示される。
- メニューシートのリンクを選ぶと、新しい画面の表示を待たずにシートを閉じる。Turbolinks の遷移が始まったら、表示が切り替わるまで `body.ba-nav-pending`（`pointer-events: none`）でタップを受け付けない。これにより、読み込み中の続けてのタップが、背後の下部ナビやシートの「ログアウト」へ通らない。覆い用の要素は置いておらず、次の場面で必ず元に戻る。
  - 新しい画面の表示・エラー画面の表示: どちらも body が入れ替わる
  - Turbolinks の通信失敗: Turbolinks がページを再読み込みする
  - キャッシュ保存前（`turbolinks:before-cache`）、`turbolinks:load`、bfcache からの復元（`pageshow`）: この状態を外す
  - フォーカスは、移った先で消える「メニュー」ボタンへ戻さない。閉じる・背景・Escape で閉じたときは、従来どおり戻す。
  - ログアウトは、シートの「ログアウト」を選んだときだけ実行される。
  - 確認は `atelier_navigation_spec.rb` の「スマホ: メニューから画面を移る間の操作」で行う。テストからサーバーの応答を止めて遅い遷移を再現し、次を確認している。
    - 連続タップしても、ログアウトにも別の画面にも移らない
    - 戻る・進む・同じ画面へのリンクの後も、元どおり操作できる
    - 読み込み中に戻る操作をしても、エラー画面になっても、操作できない状態が残らない
    - 本来のログアウトは実行できる
- 固定ナビ（上部バー・下部ナビ）は、ページ末尾の操作（スタンプ選択・お試し設定）と、保存失敗時のエラーメッセージを隠さない。
- プロフィール設定は、キャンセルで保存されず、保存するとプロフィールへ戻ってお知らせが表示される。
- プラン案内から契約プラン管理（`#plan-management`）へ移動でき、見出しが上部バーに隠れない。
- ログアウトするとドメイン共通のログイン画面へ移り、ログインし直すと Business の枠に戻る。

### 9.1 ログインの案内

**症状**: Business だけを利用している人がログインすると「音楽プラットフォームの利用には音楽ドメインの登録が必要です。」が出る。

**原因**（文言の誤りではなく、戻り先の誤り）:

1. Devise は「ログインが必要な画面を未ログインで開いた」「メール未確認・退会済みでログインに失敗した」とき、既定で**音楽のログイン画面 `/customers/sign_in`** へ戻す。Business の画面から来た人も同じだった。
2. そこでログインすると、音楽ドメインのログインとして音楽トップ `/` へ進む。
3. `/` は音楽会員向けのため、`ensure_music_domain_access_for_public_routes!` が上の案内を付けて `/business` へ戻していた。
4. パスワード再設定後も同様に `/` へ戻していた（再設定メールのリンク先は全ドメイン共通の画面）。

`/business/sign_in` から正しくログインした場合の判定（`business_user?` で Business ホーム、未登録なら利用開始画面）は元から正しかった。

**修正**:

| 場面 | 修正前 | 修正後 |
|------|--------|--------|
| 未ログインで Business の画面を開く | 音楽のログイン画面へ | Business のログイン画面へ。ログイン後は開こうとした Business の画面へ戻す |
| `/business/sign_in` でメール未確認・退会済み | 音楽のログイン画面へ（原因の文言は出る） | Business のログイン画面に原因（「メールアドレスの本人確認が必要です。」「このアカウントは退会済みです。」）を出す。ログインはさせない |
| `/business/sign_in` でパスワード違い | Business のログイン画面（変更なし） | 変更なし |
| 音楽のログイン画面から Business だけの利用者がログイン | `/` → 音楽向けの案内付きで `/business` | `/business`（またはオンボーディング）へ直接。音楽向けの案内は出ない |
| パスワード再設定後 | 全員 `/`（Business・歌声だけの利用者は音楽向けの案内付きで各ドメインへ） | 利用資格に応じて直接: 音楽会員・管理者は `/`（従来どおり）、それ以外は 歌声 → Business → Learning の順 |
| Business 未登録の人が `/business/sign_in` でログイン | 利用開始画面 `/business/join` | 変更なし（「Businessドメインの利用を開始しますか？」） |
| Business の画面からログアウト | `/business/sign_in` | 変更なし |

- 実装: `lib/customer_auth_failure_app.rb`（Devise の失敗時の戻り先。元のパスが `/business` 配下のときだけ Business のログイン画面にする。Warden は失敗処理の前にパスを書き換えるため `attempted_path` で判定）、`Public::SessionsController#business_after_sign_in_path`、`ApplicationController#business_only_customer?`、`Public::PasswordsController#after_resetting_password_path_for`。

**ログイン後の戻り先の復元（追加）**:

- 保存されるのは、未ログインで開いた GET の画面のパスだけ（Devise の既定。ホスト名は保存されない）。
- 戻すのは Business のログイン（または音楽のログイン画面から入った Business だけの利用者）のときだけ。`/business` 配下のパスに限り、`//` や `\` を含むもの、ログイン・新規登録・パスワード再設定・利用開始の画面（ループの原因）は使わず Business ホームへ。
- 保存された戻り先は、どのドメインのログインでも1回で取り出して捨てる。古い戻り先が後の音楽・歌声ログインに残らない。
- Business 未登録の人は利用開始画面、メール未確認・退会済みはログイン画面のまま（戻り先があっても制限は変わらない）。
- 「Business だけの利用者」は、Business 登録あり・音楽と歌声の登録なし・システム管理者でない人。歌声も使う人の行き先は従来どおり（音楽トップ経由で歌声へ）とし、音楽・歌声側の動作を変えない。
- 共通の認証基盤（Devise の設定・`DomainScopedSession`・音楽ガード）は分岐の追加だけで、音楽・歌声のログイン後の行き先は変えていない（request spec で確認）。

### 9.3 参加ボタンが見つからなかった原因

実際の画面を一般利用者・管理者で確認した結果（改修前の画面は下表）:

1. **管理者（システム管理者・運営者）にはボタンが出ず、理由も出ない**: `can_manage_community?` が真になるため、どのコミュニティでも「運営者」バッジだけが出ていた。プロジェクトでも「参加中」とだけ出ていた。管理者アカウントで確認するとボタンが見つからない。
2. **ホームから探しにくい**: 音楽コミュニティに参加していると一覧が空にならず、Business の探す導線が見出し横の小さな文字リンクだけになっていた（音楽の導線と並んでいた）。
3. **一覧カードに状態・導線がない**: カード全体がリンクだが、参加状況や「詳細へ」の表示がなく、押せる場所だと分かりにくかった。
4. **プロジェクトは親コミュニティ参加後にしか見えない**（公開範囲どおり）。未参加のうちは一覧に出ず、コミュニティ詳細にも「参加するとプロジェクトを探せる」と書かれていなかった。
5. コミュニティの退出処理（`community_customers#destroy`）はあるのに、画面に退出の導線がなかった。

一般利用者が未参加の Business コミュニティ詳細を開いた場合は、改修前もボタン自体は表示されていた（SP でも固定ナビに隠れない位置）。

```
     ├ ログイン（Business 未登録＝音楽・歌声だけの人）
     │     → /business/join「利用を開始」→ 元のページ（利用開始だけでは参加・申請しない）
     └ 新規登録 → 確認メール送信の案内（/business/sign_in）
           ├ 同じブラウザで確認リンク → 自動ログイン → 元のページ
           └ 別のブラウザ・アプリで確認リンク → そのブラウザでは Business ホーム（戻り先を持たない）
                 → 元のブラウザ（共有URLを開いたほう）に戻ってログイン
                    → オンボーディング → 完了後に元のページ

ログイン済みで Business 未登録（音楽・歌声だけ）の人が共有URLを開く
 └→ /business/join「利用を開始」（「参加するには、NAKAMA（Business）の利用開始が必要です。」）→ 元のページ

元のページがプロジェクトで、親コミュニティに未参加
 └→ 親コミュニティの通常画面へ転送し「先にコミュニティへの参加が必要です」＋参加ボタン（従来どおり）
```

- 戻り先の判定は `BusinessReturnPath`（新規 concern）にまとめ、ログイン（`Public::SessionsController`、既存処理を移しただけ）・確認メール（`Public::ConfirmationsController`）・利用開始（`Business::JoinsController`）・オンボーディング完了（`OnboardingsController#complete`）で再利用。使うのは Devise が保存した戻り先だけで、URL パラメータからは受け取らない。`/business` 配下のパスのみ、`//`・`\`・ログイン/登録/パスワード/利用開始の画面は除外（外部転送・ループ防止）。オンボーディング中は専用のセッションキーに1回だけ預け、使ったら消す。
- 参加・閲覧の条件は変えていない。未参加・承認待ち・停止中の人にはコミュニティの紹介と状態だけを出し、会話・プロジェクト・メンバー・スレッド・添付は出さない（request spec で本文・名前が含まれないことを確認）。
- 今回は未ログイン向けの公開プレビュー・OGP への会員データ掲載は追加していない（未ログインはログイン画面へ転送）。

戻り先を保持できない経路（制約。新しいトークンなどは追加していない）:

| 経路 | 結果 | 理由 |
|------|------|------|
| 確認メールを別のブラウザ・アプリ（LINE 内ブラウザで登録 → メールアプリから Safari など）で開く | そのブラウザでは Business ホーム。元のブラウザでログインし直せば元のページへ戻る | 戻り先は登録したブラウザのセッション（Cookie）にだけある |
| 登録後にブラウザを閉じてから確認・ログインする | Business ホームになる場合がある | `session_store` は Rails 既定（有効期限なしのセッション Cookie）。閉じると消えるかはブラウザ次第（スマホは復元することが多い）で、実機では未確認 |
| オンボーディング step3 で投稿して完了する | 投稿の詳細画面 | 投稿を見せる既存の流れを優先し、預かった戻り先は捨てる |
| 戻り先が Business 以外・外部・ログイン系の画面 | Business ホーム | 外部転送・ループ防止のため使わない |

### 13.3.1 Business 利用資格の確認（追加修正）
